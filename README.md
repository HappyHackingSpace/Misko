Behavioral test management system for laboratory mice.

Mişko aims to manage, from a single place, the behavioral tests run on mice in
biology labs. Test scenarios (pool, maze, stick, path), subjects, test devices
and the tests themselves are all defined and tracked through the application.

## Features

- **Authentication** — JWT + bcrypt. **Internal SaaS**: there is no public sign-up. The superadmin is created automatically at Docker startup (a strong password is generated by the system); all other users are created **internally** by an ADMIN.
- **Scenarios** — 4 fixed apparatus types: `POOL`, `MAZE`, `STICK`, `PATH`.
- **Subjects** — mice (code, sex, group, notes).
- **Test devices** — the phones the tests run on (Android / iOS).
- **Tests** — scenario + subject + operator + device; `PENDING → RUNNING → DONE / FAILED` status flow.
- **Comments**: a discussion thread on every test. Any signed-in user can post (stored as plain text, rendered escaped); authors edit/delete their own, privileged roles moderate. Per-user rate limit.
- **Dashboard** — summary counts and recent tests.

## System boundary — the CV service is separate

Mişko is the **system of record** for the lab workflow (test/subject/scenario/result).
The camera + computer-vision (CV) side is a **fully independent** service
(Python/FastAPI/YOLOv8, with its own PostgreSQL). Heavy data — frame-by-frame
telemetry, events, video — lives in the **CV service**; Mişko only stores the
test's **summary metrics** and artifact URLs.

How the two systems talk to each other (test ↔ capture session mapping, result
push contract, service-to-service auth) is documented in
**[docs/INTEGRATION.md](docs/INTEGRATION.md)**.

## Quick start (Docker — recommended)

The whole stack with a single command (PostgreSQL + API + Nginx):

```bash
cp .env.example .env          # edit JWT_SECRET etc. if needed
docker compose up -d --build
```

- Frontend: http://localhost:8080
- API: http://localhost:4000/api
- Migrations are applied automatically on container startup (`prisma migrate deploy`).

The **superadmin** is created automatically on startup (`ADMIN_EMAIL`, default
`admin@miskolab.com`). The system **generates a strong password** and writes it to the
backend log **once**:

```bash
docker compose logs backend | grep -A6 SUPERADMIN
```

Log in with that password, then change it and create the other users from the
**Users** screen inside the panel.

To load sample domain data (4 scenarios + subject `F-001`):

```bash
docker compose exec backend node prisma/seed.js
```

## Local development

Run PostgreSQL with compose and develop the apps locally:

```bash
docker compose up -d db        # database only

# Backend
cd backend
cp .env.example .env
npm install
npm run db:migrate             # prisma migrate dev
npm run db:bootstrap           # create the superadmin (prints password to console)
npm run db:seed                # sample domain data (optional)
npm run dev                    # http://localhost:4000

# Frontend (separate terminal)
cd frontend
npm install
npm run dev                    # http://localhost:5173  (/api → :4000 proxy)
```

## Login

When the superadmin bootstrap runs (`npm run db:bootstrap` or Docker startup),
the email is taken from `ADMIN_EMAIL` and the **password is generated by the
system and printed to the console/log once**. There is no fixed/default password
in this system — and no public sign-up either.

New users are created from the **Users** screen (ADMIN only) inside the panel; if
the password is left blank, the system generates one and shows it once.

## API (overview)

| Method | Path                 | Description                    |
|--------|----------------------|--------------------------------|
| GET    | `/api/health`        | Health check (public)          |
| POST   | `/api/auth/login`    | Login, returns JWT             |
| GET    | `/api/auth/me`       | Session info                   |
| CRUD   | `/api/users`         | User management (ADMIN)        |
| CRUD   | `/api/scenarios`     | Scenarios                      |
| CRUD   | `/api/subjects`      | Subjects                       |
| CRUD   | `/api/devices`       | Devices                        |
| CRUD   | `/api/tests`         | Tests (status transitions)     |

All endpoints except `/api/auth/*` and `/api/health` require
`Authorization: Bearer <token>`. Errors return a uniform JSON shape:
`{ "error": string, "details"?: any }`.

## CI/CD

**Separate**, path-filtered GitHub Actions pipelines for `backend/**` and
`frontend/**`:

- **Backend CI** — with a PostgreSQL service: `npm ci` → `prisma generate` →
  lint → `prisma validate` → `migrate deploy` → boot/health smoke test →
  Docker image build.
- **Frontend CI** — `npm ci` → lint → `vite build` → artifact upload →
  Docker image build.
